# MediPass — QR кодтой яаралтай тусламжийн карт

Хэрэглэгч өөрийн эрүүл мэндийн яаралтай мэдээллийг бүртгэж, QR код үүсгэнэ. QR уншуулсан хүн зөвхөн
хэрэглэгчийн **зөвшөөрсөн** мэдээллийг харна. Сэдэв: **QR + Authentication + Privacy**.

## Үндсэн боломжууд
| Хэсэг | Боломж |
|---|---|
| Authentication | Бүртгэл/нэвтрэлт, bcrypt (cost 12), JWT (HS256) httpOnly cookie, 5 буруу оролдлогод 15 мин түгжих, IP + имэйлээр атомар rate limit, хэрэглэгч байгаа эсэхийг ил гаргахгүй нэгдсэн алдааны мессеж, **имэйлээр нууц үг сэргээх**, түгээмэл нууц үгийн хориг, нууц үг солиход бусад сешн хүчингүй, бүх төхөөрөмжөөс гарах |
| Privacy | Талбар бүр 3 түвшин (Нээлттэй / PIN / Нуусан), PIN хамгаалалт (10 мин түр нээлт, IP бүрт болон картад нийт буруу оролдлогын хязгаар), AES-256-GCM шифрлэлт (түлхүүр солих боломжтой), IP хэш + маск, карт түр зогсоох, хугацаа тогтоох, QR токен шинэчлэх, өгөгдөл JSON-оор татах, бүртгэл устгах |
| QR | 128 битийн таамаглах боломжгүй токен, PNG/SVG татах, түрийвчний карт хэвлэх (85.6×54мм), утасны түгжээний дэлгэцийн зураг үүсгэх |
| Яаралтай хуудас | Утсанд зориулсан, 103 руу нэг товчоор залгах, холбоо барих хүн рүү залгах, байршлыг SMS-ээр илгээх, MN/EN хэл |
| Бусад | Хандалтын түүх + 14 хоногийн график, аюулгүй байдлын үйл явдлын бүртгэл, dark mode, PWA manifest, security headers + CSP, өдөр бүрийн автомат цэвэрлэгээ, unit тест, CI |

## Технологи

## 1. Локал дээр ажиллуулах (VS Code)

Шаардлага: **Node.js 20+** болон **PostgreSQL** (Docker эсвэл үнэгүй [Neon](https://neon.tech)).

**Docker-тай:**
```bash
npm install
docker compose up -d
cp .env.example .env      # Windows: copy .env.example .env
npm run setup             # AUTH_SECRET, ENCRYPTION_KEY-г автоматаар үүсгэж, хүснэгтүүдийг үүсгэнэ
npm run dev
```

**Docker-гүй (Neon):** https://neon.tech дээр үнэгүй Project үүсгэж "Connection string"-ээ хуулаад `.env` доторх `DATABASE_URL`-д тавина (`docker compose` алхмыг алгасна), дараа нь `npm run setup`, `npm run dev`.

Хөтөч дээр http://localhost:3000/register нээж бүртгүүлнэ.
Бүртгэл хадгалагдсаныг шалгах:
```bash
npm run db:studio         # User, Profile, Card хүснэгтүүдийг харна
```

### Бүртгэл ажиллахгүй бол
Одоо алдаа хуудас дээр шалтгаан нь шууд бичигдэнэ:
| Мессеж | Шийдэл |
|---|---|
| хүснэгтүүд үүсээгүй | `npm run setup` (эсвэл `npx prisma db push`) |
| өгөгдлийн сантай холбогдож чадсангүй | `.env`-д `DATABASE_URL` зөв эсэх, PostgreSQL ажиллаж байгаа эсэх |
| AUTH_SECRET / ENCRYPTION_KEY дутуу | `npm run setup` |

### Нууц үг сэргээх (имэйл)
`/forgot` хуудаснаас имэйлээр 30 минут хүчинтэй, нэг удаагийн холбоос илгээнэ. Токены зөвхөн SHA-256 хэшийг өгөгдлийн санд хадгална.
- **Локал**: `RESEND_API_KEY` тохируулаагүй үед холбоос **`npm run dev` ажиллаж байгаа терминалд** хэвлэгдэнэ.
- **Production**: [Resend](https://resend.com)-ээр API key авч `RESEND_API_KEY`, `MAIL_FROM`-ийг тохируулна.
- Эрүүл мэндийн мэдээлэл нууц үгээр биш сервер талын түлхүүрээр шифрлэгдсэн тул нууц үг сэргээхэд өгөгдөл устахгүй.

### Тест

npm run typecheck

## 2. Vercel дээр байршуулах

1. Кодыг GitHub дээр шинэ repository болгон push хийнэ.
2. https://vercel.com → **Add New → Project** → repository-оо сонгоно.
3. Төсөл үүссэний дараа **Storage → Create Database → Neon (Postgres)** сонгож төсөлдөө холбоно.
   Энэ нь `DATABASE_URL` орчны хувьсагчийг автоматаар нэмнэ.
4. **Settings → Environment Variables** хэсэгт нэмнэ:
   - `AUTH_SECRET` — дээрх командаар үүсгэсэн утга
   - `ENCRYPTION_KEY` — 64 тэмдэгт hex
   - `NEXT_PUBLIC_APP_URL` — `https://таны-төсөл.vercel.app` (өөрийн домэйн холбосон бол тэр домэйн). **Localhost утга тавихгүй!** Хоосон орхивол Vercel-ийн production домэйн автоматаар ашиглагдана.
   - `RESEND_API_KEY`, `MAIL_FROM` — нууц үг сэргээх имэйлд (заавал биш боловч зөвлөнө)
   - `CRON_SECRET` — дурын урт санамсаргүй тэмдэгт мөр. `vercel.json` дахь cron өдөр бүр хуучин rate limit, хандалтын түүх (180 хоног), аюулгүй байдлын бүртгэл (365 хоног)-ийг цэвэрлэнэ
5. Хүснэгт үүсгэх: локал компьютер дээрээ `.env`-д Neon-ий холбоосыг тавиад `npm run setup` (эсвэл `npx prisma db push`) ажиллуулна.
6. **Deployments → Redeploy** дарна. Бэлэн!
7. **QR-аа дахин татна**: деплой хийсэн сайтдаа нэвтэрч **QR код ба карт** хэсгээс QR-аа шинээр татаж/хэвлэнэ. Localhost дээрээс татсан хуучин QR зөвхөн таны компьютер дээр нээгддэг тул хэрэггүй. (Токен өөрчлөгдөөгүй, зөвхөн домэйн шинэчлэгдэнэ.)
8. **Шалгах**: утсаараа QR-ыг уншуулж, wifi-гүй (мобайл дата) байхад яаралтай хуудас нээгдэж байгаа эсэхийг үзнэ.

> ⚠️ Vercel → Settings → **Deployment Protection**: QR уншуулсан хүн нэвтрэхгүйгээр нээх ёстой. Production домэйн нийтэд нээлттэй байх ёстой; харин `...-git-...vercel.app` гэх мэт preview хаягаар QR үүсгэж болохгүй (түгжигдсэн байдаг).
>
> Локал дээр утсаас туршихыг хүсвэл компьютерийнхээ LAN хаягаар (`http://192.168.x.x:3000`) нээвэл QR тэр хаягаар үүснэ.

> ⚠️ `ENCRYPTION_KEY`-г дараа нь солих юм бол хуучин шифрлэгдсэн мэдээлэл уншигдахгүй болно. Түлхүүрээ аюулгүй хадгална уу.

### Түлхүүр солих (ENCRYPTION_KEY rotation)
1. Өгөгдлийн сангийн нөөц хуулбар авна.
2. `.env`-д хуучин түлхүүрээ `ENCRYPTION_KEY_OLD`-д, шинэ түлхүүрээ `ENCRYPTION_KEY`-д тавина.
3. `npm run rotate-key` — бүх профайлыг шинэ түлхүүрээр дахин шифрлэнэ.
4. Амжилттай бол `ENCRYPTION_KEY_OLD`-ийг устгана.

(`ENCRYPTION_KEY_OLD` байх хооронд апп хуучин өгөгдлийг ч уншиж чадна.)

### Аюулгүй байдлын тэмдэглэл
- PIN: IP бүрт 15 минутад 5 оролдлого + картад нийт цагт 25 **буруу** оролдлого. Сүүлийнх хэтэрвэл PIN-ээр хамгаалсан мэдээлэл тухайн цагийн хугацаанд түр хаагдана (нээлттэй талбарууд харагдсаар). 6 оронтой PIN-г зөвлөнө.
- Хэрэглэгчийн IP-г `x-real-ip` (байхгүй бол `X-Forwarded-For`-ийн сүүлийн утга)-аас авна. Vercel дээр зөв ажиллана; өөр прокситой бол прокси нь эдгээр толгойг өөрөө тавьдаг эсэхийг шалгана уу.
- CSP-д Next.js-ийн шаардлагаар `'unsafe-inline'` байгаа (nonce-д шилжих нь цаашдын сайжруулалт).
